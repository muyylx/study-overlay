# Scanner Access 3.115: аудит скорости и распознавания

Дата: 23 ноября 2026 года

## Что было найдено

- В активном Cloudflare Worker ровно шесть модулей: index.js, ui.js, owner-client.js, owner.js, providers.js, sources.js. Старые release-версии и client-v*.js в GitHub не загружаются текущим Worker и не увеличивают время ответа только своим наличием.
- OCR-фото раньше фиксированно уменьшалось до 2200 пикселей по длинной стороне; сильное JPEG-сжатие могло ухудшать чтение текста.
- Режим «Разобрать» читает HTML-страницу и не превращает загруженный снимок в текст. Это не ошибка OCR, а отдельная функция.
- Задержка первого OCR-ответа включает подготовку файла, передачу и один запрос к назначенной Vision-модели (тайм-аут на стороне Worker 16 секунд). Измерения реальной скорости сторонней модели пока не получены.

## Изменения 3.115

- В пользовательской панели добавлена кнопка «📷 Лист на странице» для ручного чтения большого img/canvas. Поиск предпочитает крупные вертикальные изображения в основном содержимом, затем пробует body, до четырёх кандидатов при ошибке доступа; если сайт блокирует доступ к фото (CORS или сторонний iframe), пользователь получает понятный совет сделать скриншот.
- Снимок из галереи сохраняет разрешение до 2600 пикселей по длинной стороне. Для PNG пробуется lossless-изображение с лимитом 1,95 млн символов Data URL. Если файл больше, JPEG сжимается постепенно, уменьшая разрешение только при необходимости.
- Результат OCR хранится только в памяти текущей панели и повторно используется при передаче побайтово одинакового изображения от того же пользователя. При изменении API/моделей администратором кэш сбрасывается. Это ускоряет повторное чтение без нового расхода лимита API, не гарантирует ускорения первого запроса.
- В интерфейсе показываются общее время, время подготовки картинки, время Vision-модели, количество прочитанных строк и формат подготовленного изображения.
- OCR-инструкция требует не угадывать нечитаемые символы и сохранять номера, пропуски и знаки препинания. Сервер возвращает quality='review-needed' при наличии неразборчивых фрагментов, иначе quality='unverified'.
- Существующая система сессий, пользователи D1, API-ключи, механизмы выбора моделей для прежнего /api/solve и личная админ-закладка владельца 3.111 не менялись.

## Ограничения

- 100% точности OCR или ответов гарантировать нельзя без проверки на размеченном наборе реальных заданий; эту работу не заменяет согласие двух ИИ-моделей.
- Загрузка картинки напрямую ограничена CORS, iframe и политиками Safari. Не все изображения на странице будут доступны.
- При первом распознавании нужно дождаться сторонней OCR-модели. При наличии большого PNG первоначальная подготовка может даже стать медленнее; необходимы реальные замеры.
- Сохраняется ранее выявленный риск размещения сырого токена в localStorage произвольного посещаемого сайта при резервном способе входа. Его нельзя считать защищённым; требуется отдельная миграция авторизации, прежде чем рекомендовать использование на недоверенных сайтах.
- Рабочий код проверен синтаксически и по наличию маршрутов, но iPhone Safari и ответы APInex на реальном снимке не испытаны.

# Scanner Cloud 3.103 · обновление 22 ноября 2026 года

**Личная версия владельца, не Scanner Access.** Клиент и сервер обновлены, старые версии 3.100/3.101 остаются доступными.

## Что реализовано

- [Новый клиент 3.103](./client-v3.103.js): отдельный файл; старые сборки не перезаписаны.
- [Обновление личной Safari-закладки](./update.html): берёт токен из **скопированного адреса старой рабочей закладки** локально в Safari. Токен не отправляется на установочный сайт и не публикуется в GitHub. Если в старой закладке нет действующего токена, перенос не сработает.
- **Количество вариантов:** для одиночного вопроса клиент показывает одну букву/фигуру; для явно многовариантного вопроса допускает несколько. Проверка расположена рядом с вопросом и учитывает радио-кнопки/чекбоксы, а не весь текст страницы.
- **Никакого ответа «Модели разошлись»**: сервер выбирает один результат при одиночном вопросе, сохраняя внутренний признак неопределённости. Если ни одна модель не дала допустимый вариант, UI сообщает об ошибке вместо выдуманной буквы.
- **Надёжность:** одна дополнительная попытка только при HTTP 502/503/504; лимит ожидания около 29 секунд; восстановление после отмены, ограничения повторов.
- **Скорость сервера:** при согласии моделей глубокий путь не ждёт Wikipedia/Wikidata. При сомнениях источники по-прежнему проверяются, может подключиться дополнительная модель.
- **Безопасность:** прежний личный токен доступа, секреты провайдеров и лимит запросов в Cloudflare сохранены. Код ничего не нажимает и не отправляет вместо пользователя.

## Проверки

Проверены синтаксис JS, распознавание одиночных/множественных вопросов (русский, украинский, чекбоксы и радио-кнопки), формат ответов сервера и обработка расхождений. Cloudflare подтвердил активную публикацию обновлённого Worker на 100% трафика с прежними секретами и ограничением запросов.

**Не проверено в реальном Safari на iPhone:** фактическое получение ответа через приватную закладку и качество ответов ИИ на настоящих вопросах. Гарантия правильности ответов или измеренное ускорение не заявляются.

Установить на чужой телефон и прочитать сохранённые закладки удалённо невозможно. Изменения сервера применяются к старым рабочим закладкам автоматически; для новых функций интерфейса требуется заменить код своей Safari-закладки.

# Scanner Cloud 3.100 · быстрый режим Kahoot

## Что обновлено

- **Личный Scanner Cloud**: версия `v3.100` под плавающей панелью. Требуется заменить код старой Safari-закладки новым личным файлом из чата.
- Kahoot: распознавание вариантов по цветам и фигурам, включая вопросы с 2 или 4 вариантами. UI отображает только краткий результат: `▲ (красный)`, `◆ (синий)`, `● (жёлтый)` или `■ (зелёный)`. Панель можно свернуть.
- Kahoot: сканирование по содержанию вопроса без привязки к текущей секунде таймера; авто проверяет изменения чаще, но не отправляет один вопрос повторно.
- Сервер: `/solve?quick=1` запускает быстрые модели параллельно и отдаёт первый пригодный результат, не ожидая длинной проверки Википедии. Если второй ответ приходит почти одновременно, модельные ответы сравниваются. Для вопросов, явно опирающихся на картинку, текстовая модель не имеет приоритета.
- Обычный разбор НаУрок продолжает использовать прежнюю глубокую логику с материалами Википедии и дополнительными проверками.
- Частный токен остаётся только в личной закладке; **этот публичный исходник с `__SCANNER_PRIVATE_TOKEN__` не запускается без приватной настройки**.

## Проверки и ограничения

- Chromium: 4 теста (считывание цветных вариантов, формат ответа, защита от повторного запроса при изменении таймера, реакция на новый вопрос и сворачивание).
- Worker с имитацией API: 3 теста (быстрый текстовый ответ, приоритет Vision для картинки, быстрый текстовый путь для необязательного изображения).
- Локальные замеры со специально заданными задержками **не являются фактическим временем ответа настоящих ИИ**. Нельзя гарантировать ответ за 10 секунд: сеть, лимиты и задержки провайдеров могут помешать.
- При одном ответе отображается отметка «Предварительно». При разногласиях нет гарантии правильного выбора.
- Реальное поведение в Safari на iPhone и в Kahoot ещё не подтверждено.
- Ни один скрипт не нажимает ответы и не отправляет тест.

Исходники: [client-v3.100.js](./client-v3.100.js), [worker-v3.100.js](./worker-v3.100.js). Автотесты: [браузер](./tests/test_v3_100_client.py), [сервер](./tests/test_v3_100_worker.mjs).

# Архив изменений v6.1
Компактная Safari-панель для разбора учебных вопросов. Это публичный **исходник без секретов**; здесь намеренно используется `__SCANNER_PRIVATE_TOKEN__`.

## Что изменилось
- Кнопка **−** сворачивает всю панель до переносимого кружка **⌕**. Нажатие на кружок снова раскрывает её.
- Автоматическое сканирование ждёт **два последовательных стабильных снимка** вопроса, прежде чем обращаться к Worker.
- Ручной запуск и авто используют один отпечаток: **один запрос на один неизменившийся вопрос** в авторежиме, даже если запрос завершился ошибкой.
- В отпечаток входят текст, варианты и стабильные адреса/подписи изображений; **номер вопроса исключён**, поэтому его позднее обновление не вызывает повторную отправку.\n- Выделение текста пользователем не влияет на автоматический режим.\n- После прихода ответа панель перепроверяет текущий вопрос, если страница меняется, вместо немедленного ложного предупреждения о новом задании.
- Повторный ручной разбор возвращается из кэша, если есть готовый результат. После ошибки ручная кнопка позволяет повторить запрос.
- Клиент проверяет, что сервер не прислал несуществующие буквы вариантов или несколько ответов на вопрос с одним вариантом.
- Если вопрос изменился во время выполнения запроса, устаревший ответ не показывается поверх следующего.
- Ссылки Wikipedia/Wikidata и отметка расхождения моделей остаются доступными.

## Лимиты\nCloudflare Worker: **40 запросов за 60 секунд на IP** (ранее 8). Это защитный лимит сервера; квоты AI-провайдеров действуют отдельно. Не отключайте защиту для публично доступного API.\n\n## Проверки
В локальном синтетическом браузерном тесте: 2 разных вопроса вызвали ровно 2 запроса; ручной запуск с последующим включением «авто» вызвал 1 запрос; выбор варианта после сворачивания не создал нового запроса; ошибка API не привела к циклическому авторетраю, но ручной повтор сохранился. Для v6.1 выполнено дополнительно 5 локальных проверок в Chromium: изменение только номера, ручной+авто, реальная смена текста, ошибка 429 без циклического повтора, загрузка изображения без дублирования. 5/5 прошли. Это не тест реального Safari или качества ИИ.

## Безопасность
**Не храните API-ключи и приватный токен доступа к Worker в этом публичном репозитории.** Ключи провайдеров находятся только в Cloudflare Workers Secrets. Для личной установки используйте приватный bookmarklet из диалога, не содержимое этого публичного файла напрямую. Bookmarklet сам по себе содержит отзывной токен доступа, поэтому распространять его нельзя.

Панель не нажимает варианты и не отправляет школьный тест автоматически. Совпадение ответов моделей и ссылки Wikipedia не гарантируют фактическую правильность.
