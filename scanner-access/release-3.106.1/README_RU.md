# Scanner Access / Scanner Cloud 3.106.1

Дата релиза: **2026-11-22**. Совместима с личной Safari-закладкой **3.106**.

## Что менялось
- Личные owner-токены имеют срок действия 30 суток; текущая личная сессия была сохранена.
- В админ-панели есть список личных сессий, индивидуальный отзыв и прежний отзыв всех сразу.
- Для изменяющих данные owner-запросов требуется специальный заголовок `x-scanner-admin-request: 1` и проверяется происхождение запроса.
- Число ключей владельца ограничено атомарной SQL-вставкой.
- После успешной диагностики обновляется `verified_at`.
- Добавлена смена модели существующего ключа через админ-панель: сначала валидация модели и контрольный запрос, затем запись.
- Для `openrouter/free` в панели добавлено пояснение о непредсказуемом выборе бесплатной модели.
- Разделяются состояния «ответ получен», «ответ непроверяемого формата» и «данных недостаточно».
- Для Groq GPT-OSS включён JSON object mode, текстовые составные ответы нормализуются.
- Исправлена передача количества изображений; действует общий бюджет времени для обработки запроса, предусмотрен резервный APINex-маршрут для изображений.
- Версии клиента и сервера синхронизированы на `3.106` (версия сервера после дополнительного обновления **3.106.1**), старые закладки оповещаются об обновлении.
- Удалена явная строка приватного маршрута администратора из встраиваемой личной закладки.
- Участники и их ключи APINex не сбрасывались. Модуль `providers.js` сохранён без изменений.

## Изменение D1

В таблицу `owner_sessions` добавлена колонка `expires_at INTEGER NOT NULL DEFAULT 0`.
Существующим сессиям выдан срок `created_at + 2592000`.
Новые сессии заполняют `expires_at` автоматически.

## Неподтверждённые случаи и ограничения

- Проверка реальной доступности всех провайдеров и корректности ответов на большой выборке не выполнена: запросы к публичному адресу Worker блокируются из инструментальной среды, а пользовательский Safari недоступен.
- Старый `study-overlay-3-api` (Scanner Cloud 3.103) не отключён, потому что это может нарушить работу старых закладок. Его авторизацию и секреты необходимо вывести из эксплуатации отдельно.
- `openrouter/free` является маршрутизатором свободных моделей, а не закреплённой моделью: результат и формат могут изменяться.
- Ошибки Gemini HTTP 503 могут оставаться. Создание нового ключа само по себе их не устраняет.
- Улучшения безопасности и инженерной устойчивости не гарантируют корректность любого ответа модели.

## Ручная приёмка после развёртывания

1. Открыть админ-панель и войти.
2. Проверить, что все четыре ключа перечислены без раскрытия исходного значения.
3. Использовать «Проверить все ключи», посмотреть ошибки конкретных провайдеров.
4. Проверить список сессий и индивидуальный отзыв на специально созданной тестовой закладке.
5. Создать личный код 3.106, заменить адрес своей Safari-закладки, убедиться в авторизации.
6. Проверить страницу участника и существующий код активации без переназначения его ключа.
7. Перевыпустить ранее опубликованные секреты у провайдеров.

**Сборка не считается прошедшей end-to-end тест до завершения ручной приёмки.**

## Дополнение 3.106.1

Серверный маршрут `POST /owner/keys/:id/model` требует авторизованную cookie администратора и заголовок `x-scanner-admin-request`. Он проверяет, что модель существует (когда API провайдера возвращает список), затем отправляет безопасный контрольный запрос. Настройка модели сохраняется только после успешного теста. Во время этой операции ключ не раскрывается браузеру. Не стоит менять рабочие модели только ради эксперимента: проверка доступности в моменте не гарантирует постоянной доступности.
