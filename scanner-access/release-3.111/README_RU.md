# Scanner Access 3.111 — сохранение входа и сканирование листов
Дата: 23.11.2026.

## Исправлено
- В панели участника добавлен отдельный безопасный мост для восстановления уже существующей сессии. Кнопка «Сохранить вход для других вкладок» открывает первую сторону Scanner Access; кнопка «Восстановить вход без нового кода» передаёт действующую сессию напрямую между окнами, сверяя origin/source.
- Код активации остаётся одноразовым; списки пользователей, приглашения, блокировки, отзыв сессий и шифрованные личные ключи не изменялись.
- В личной закладке владельца версия 3.111: кнопки «Прочитать текст листа» и «Фото…», JPEG до 2200 px по длинной стороне (сжатие только при необходимости).
- Серверный POST /owner/ocr защищён личной сессией владельца и общим лимитом запросов. Использует подключённый Gemini или APINex ключ владельца. Возвращает только распознанные строки, без заполнения ответов, с providerMs и elapsedMs.
- Публичный установщик scanner-cloud/update.html больше не переносит токен из старой закладки. Новую личную закладку создаёт приватная админ-панель через /owner/install.

## Что сохранено
- Cloudflare Worker scanner-access-a43f105622, все 6 JS-модулей, секреты и D1 binding.
- Данные D1 scanner-access-a43f105622-db, существующие аккаунты, активированные приглашения и сессии.
- Старый /owner/solve и авторизация участников.
- Публичный Scanner Access bookmarklet не требует замены ради новых кнопок восстановления сессии: интерфейс /panel загружается с сервера.

## Ограничения и проверки
- Проверка JS-синтаксиса пройдена. Cloudflare подтвердил публикацию на 100% и сохранение 4 bindings. OCR не проверялся на реальном Gemini/APInex и iPhone Safari.
- Safari может ограничить всплывающие окна; пользователь должен разрешить открытие окна или зайти на сервис напрямую. Если срок сессии истёк или она отозвана, потребуются обычные процедуры восстановления через администратора.
- Чужие iframe и CORS могут препятствовать считыванию изображений прямо со страницы: используйте «Фото…» с локальным скриншотом.
- Публичный GitHub Pages версии 3.2 снова направлен на историческую версию №36 Worker study-overlay-3-api, опубликованную на 100% трафика 23.11.2026. У версии №36 есть прежние bindings DB, AI, ограничения и секреты, а база study-overlay-db содержит 6 пользователей, 49 сессий и все 3 применённые миграции. Локальный архив исходников 3.2 прошёл 22/22 тестов, однако он не доказывает побайтовое совпадение с версией №36. Реальный вход через Safari и HTTP маршруты в production отдельно не проверены.
