# Scanner Cloud 3.108: быстрый поиск и дополнительная проверка

Дата релиза: 22 ноября 2026. Сервер **3.108**, личная закладка Safari **3.107** (совместима, переустановка не нужна).

## Причина обновления
Реальная проверка на учебных вопросах дала 11/24 правильных. Это оценка на одной выборке, не автоматическое измерение причины ошибок. Контрольные тесты ключей проверяли только «2+2» и поэтому не являются показателем качества на истории, литературе, географии и других дисциплинах.

Сейчас действуют четыре ключа владельца. В последней пользовательской проверке APINex, Groq, OpenRouter прошли короткий контрольный тест, Gemini не уложился в девять секунд.

## Источники
Восстановлена идея из версии 3.103:
- Wikipedia на украинском и русском через официальный MediaWiki Action API (`generator=search` вместе с `prop=extracts`).
- Wikidata через официальный `wbsearchentities`.
- Одновременно не более трёх коротких GET-запросов с осмысленным User-Agent и ограничением времени 1450–1700 мс на каждый.
- Только для подходящих фактических вопросов, без математических выражений и без визуальных задач.
- Кэш найденных справочных материалов в памяти текущего Worker с TTL 3 минуты и лимитом 48 записей.

Вопрос целиком не отправляется Wikipedia: применяется сокращённый поисковый запрос из тематических слов. Извлечённый контент считается **недоверенным справочным материалом**, не системной инструкцией и не доказательством правильности.

## Маршрутизация и ограничения времени
- Основная пара Groq + APINex по-прежнему вызывается параллельно.
- Источники ищутся **параллельно**, не до обращения к AI.
- Если модели совпали, поиск не может надолго задержать выдачу; максимум 180 мс дополнительного ожидания на пути проверки.
- При расхождении, отсутствии пригодного результата или видимом противоречии с найденной справкой дополнительная модель получает выдержки как ограниченный контекст.
- При отсутствии доступа к Wikimedia или её тайм-ауте проверка просто пропускается, а основные модели продолжают работать.
- В ответе с реально использованными источниками возвращаются URL и названия материалов. Это справка, а не гарантия истины.
- Статус «предварительно» сохраняется, если нет независимого подтверждения.

## Тесты
- 7/7 проверок синтаксиса для текущего Worker, модуля sources, Safari-кода и 4 скриптов админ-панели.
- На имитированной Wikipedia/Wikidata: вопрос про Мольера запускает поиск, математический запрос — нет, дополнительная модель получает реальные выдержки, имена и URL источников попадают в ответ.
- При отказе Wikipedia (имитация 403) основная модель продолжает выдавать ответ.
- При зависшем поиске добавочная пауза для согласованного ответа ограничена примерно 180 мс в синтетическом тесте.
- На этапе деплоя D1 имела 4 ключа, 3 owner-сессии, 1 участника.
- Cloudflare version id: `090211e8-85cf-494c-8d6a-f2d90a205550`, 100% трафика.

## Важные ограничения
Реальные HTTP-запросы к Википедии из инструментальной среды получают 403 с текстом «Forbidden: requests to uk.wikipedia.org are not allowed». Это ограничение внешней инструментальной среды; доступность Wikipedia именно из запущенного production Worker **не подтверждена**. Реальная проверка Safari и провайдеров API здесь также не проводилась.

Согласие двух AI не доказывает правильность: они могут ошибаться одинаково. Wikipedia/Wikidata не всегда содержат правильный ответ к конкретной школьной формулировке. Увеличение числа API-вызовов не гарантирует улучшение точности. Нужно сравнить результаты на том же наборе из 24 вопросов с проверенными правильными ответами, записывая отдельно ошибки извлечения вопроса, отсутствие источника, ошибку модели и тайм-аут.
